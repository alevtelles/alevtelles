## 👋 Sobre mim

Atuo com **Engenharia de Software, Arquitetura e Inteligência Artificial**, participando desde a definição técnica e arquitetural até a implementação e evolução de sistemas em produção.

Minha atuação conecta principalmente:

- **Arquitetura de Software & IA**
- **Product Engineering**
- **Engenharia de Dados**
- **IA Generativa**
- **AI Agents e sistemas multiagentes**
- **AI-Assisted Development**
- **Harness Engineering**
- **Sistemas distribuídos e arquiteturas orientadas a eventos**

Trabalho com arquitetura de software, APIs, backend, integrações, plataformas de dados e soluções de Inteligência Artificial aplicadas a ambientes corporativos e financeiros.

Nos últimos anos, concentrei parte importante do meu trabalho em **LLMs, RAG, agentes de IA, sistemas multiagentes e MCP**, além da estruturação de contexto, ferramentas, validações, avaliação e observabilidade para sistemas baseados em IA.

Minha atuação continua sendo **hands-on**: arquitetura e implementação fazem parte do mesmo processo.

# 🏗️ Projetos em destaque

## 💳 Triagem Inteligente de Atendimento com JEV

Projeto aplicado a um cenário bancário de atendimento de cartão de crédito utilizando **JEV**, da TypeSafe, para construção de decisões estruturadas com IA.

A solução explora um modelo diferente do uso tradicional de LLMs: em vez de depender de texto livre para tomar decisões, utiliza estados, perguntas tipadas e respostas estruturadas.

O projeto aborda:

- classificação de intenção;
- triagem de atendimento;
- decisões estruturadas;
- fluxo baseado em estado;
- arquitetura de referência;
- integração com serviços;
- separação entre decisão e geração de linguagem.

## 🤖 Sistemas Agênticos

Arquiteturas para agentes de IA integrados a sistemas corporativos, APIs, ferramentas, dados e bases de conhecimento.

Uma arquitetura de agentes não é apenas um prompt conectado a um modelo.

Ela envolve:

```text
Usuário / Sistema
        │
        ▼
    Orquestração
        │
        ├── Contexto
        ├── Estado
        ├── Memória
        ├── Ferramentas
        ├── RAG
        ├── APIs
        └── Guardrails
        │
        ▼
     AI Agent
        │
        ▼
   Avaliação
        │
        ▼
 Observabilidade
        │
        ▼
   Governança
```

## 🛡️ Arquiteturas para análise de fraude

Arquiteturas híbridas que combinam software tradicional, dados, regras, modelos e agentes de IA.

Um fluxo típico pode combinar:

```text
Transação
    │
    ▼
Regras determinísticas
    │
    ▼
Modelos de risco
    │
    ▼
Event Stream
    │
    ▼
Agentes especializados
    │
    ├── Triagem
    ├── Documentos
    ├── Pesquisa
    ├── Compliance
    └── Revisão
    │
    ▼
Decisão / Dossiê
```

Principais preocupações arquiteturais:

- idempotência;
- rastreabilidade;
- explicabilidade;
- auditoria;
- fallback;
- processamento assíncrono;
- observabilidade;
- governança.

# 🧠 Como penso sistemas de IA

IA não deve ser tratada como uma camada isolada da aplicação.

Um modelo pode ser uma parte importante da solução, mas sistemas de IA em produção dependem de muito mais do que prompts.

Penso a arquitetura como um conjunto de camadas:

```text
Negócio
   │
   ▼
Arquitetura
   │
   ▼
Software
   │
   ▼
Dados
   │
   ▼
Contexto
   │
   ▼
Modelos
   │
   ▼
Agentes
   │
   ▼
Ferramentas
   │
   ▼
Avaliação
   │
   ▼
Observabilidade
   │
   ▼
Governança
```

Entre os pontos que considero estão:

- contratos;
- estado;
- contexto;
- memória;
- ferramentas;
- integração;
- segurança;
- guardrails;
- avaliação;
- fallback;
- custo;
- latência;
- rastreabilidade;
- governança;
- comportamento em produção.

# 🧩 AI-Assisted Development & Harness Engineering

Também trabalho com o uso de IA dentro do próprio processo de desenvolvimento de software.

O objetivo não é apenas utilizar um modelo para gerar código, mas construir um ambiente no qual agentes possam trabalhar com contexto, ferramentas, regras e validações adequadas.

```text
Especificação
     │
     ▼
Contexto
     │
     ▼
Agente de desenvolvimento
     │
     ├── Código
     ├── Ferramentas
     ├── Documentação
     ├── Arquitetura
     └── Regras
     │
     ▼
Validação
     │
     ├── Testes
     ├── Lint
     ├── Types
     ├── Segurança
     └── Avaliação
     │
     ▼
Implementação
```

# 📐 Princípios que guiam meu trabalho

```text
Arquitetura antes da ferramenta.

Contexto antes do prompt.

Contratos antes da integração.

Observabilidade desde o início.

Avaliação antes de confiar na saída.

Dados como parte da arquitetura.

IA integrada ao sistema, não isolada dele.

Automação sem perder rastreabilidade.

Decisões técnicas considerando operação e evolução.
```
